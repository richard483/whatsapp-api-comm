# whatsapp-api-comm

HTTP API around the [`@whiskeysockets/baileys`](https://github.com/WhiskeySockets/Baileys)
WhatsApp client. Exposes contacts, groups, messages (send/receive/edit/revoke/react/forward),
media (upload + decrypted download), polls, location, vcards, presence, chat-level controls
(archive/pin/mute/mark-unread/disappearing), privacy/blocklist, and the bot's own profile —
all backed by a PostgreSQL message store.

## API documentation

There are two views of the API surface — both are kept in sync with the routes:

| What | Where | Source of truth |
|---|---|---|
| **Interactive Swagger UI** | `http://<host>:<port>/api-docs` | generated at boot |
| **Raw OpenAPI 3.0 spec** | `http://<host>:<port>/api-docs.json` | generated at boot |
| Postman collection (legacy reference) | [`document.md`](./document.md), [`postman_collection.json`](./postman_collection.json) | hand-maintained |
| Future-work notes | [`docs/future-improvements.md`](./docs/future-improvements.md) | — |

The Swagger spec is generated by [`swagger-jsdoc`](https://github.com/Surnet/swagger-jsdoc)
from `@openapi` blocks at the top of each `src/routes/*.ts` file, so anything you see in
the UI is wired to a real route. The Postman collection is kept around as a quick smoke-test
reference; treat Swagger as the authoritative API documentation.

For local development the URLs default to:
- Swagger UI: <http://localhost:3000/api-docs>
- Raw spec:   <http://localhost:3000/api-docs.json>

## Quick start

```bash
npm install
npm run build
npm start
# first run will print a QR code in the terminal — scan it with WhatsApp on your phone
```

Environment:

| Variable | Purpose |
|---|---|
| `PORT` | HTTP port (default `3000`) |
| `DB_AUTO_ALTER` | set `true` to let Sequelize `ALTER` tables on boot (dev / first deploy only) |
| Postgres connection vars | see `src/config/sequelize-config.ts` |

## Feature surface (high level)

- **Messages**: send text / media (base64 or URL) / audio (incl. voice notes) / polls /
  locations / vcards; reply (quote), edit, revoke, react, forward, mark-as-read.
- **Media**: upload via base64 or `media_url`; download decrypted inbound media as a
  binary stream (or `?as=base64` for JSON).
- **Chat**: presence/typing, archive, pin, mute, mark-unread, mark-everything-read,
  disappearing-messages toggle.
- **Contacts**: CRUD, WhatsApp existence check (`onWhatsApp`).
- **Groups**: create, join (by code or URL), leave, list, refresh metadata, edit subject /
  description / announce / locked, add/remove/promote/demote, invite-code (read & revoke),
  pending join-requests (list, approve, reject).
- **Profile**: read/update bot name, status, picture; connection status.
- **Privacy**: blocklist (read, block, unblock), privacy settings (read, patch), profile
  picture of an arbitrary JID / contact / phone number.
- **Schedule**: persist and dispatch outbound messages at a future time.

Refer to `/api-docs` for the exact request/response shape of every endpoint.
